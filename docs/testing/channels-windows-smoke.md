# 视频号 Windows 真机验收（v2.0.3）

> 本清单是视频号功能的**发布硬门禁**。自动测试（pytest / node --test /
> ruff / build）全绿只证明代码自洽，**不构成**真机通过。未按本清单逐项
> 验收前，不得创建正式 Release。
>
> **推荐用法**（v2.0.3 真机结论）：单个目标视频用**分享链接下载**
> （A 组，最稳）；持续刷视频捕获用 `--channels` + 页面按钮（B 组）。
> 微信内页面数据经原生桥接下发（不走 HTTP），A/B/C 捕获策略对
> `/web/pages/*` 无效——这是已实证的结论，B 组按钮拿不到 Feed 时按第 14 项
> 的诊断路径处理，不算阻塞项。

## 0. 环境准备

| 项 | 要求 |
| --- | --- |
| 系统 | Windows 10 / 11（x64） |
| 微信 | **PC 版微信（WeChatAppEx.exe，内嵌 Chromium）**，记录版本号 |
| Python | 3.10+（mitmproxy 10+ 要求），已 `pip install -e .[channels]` |
| 依赖 | 直播录制需要 ffmpeg（普通视频下载不需要） |
| 网络 | 微信可正常联网；**关闭**其它 VPN / 加速器 / 代理软件 |

记录信息（验收报告需要）：

```text
微信版本：微信 3.x.x（帮助 → 关于微信）
Windows 版本：
Python 版本：
工具版本：v2.0.2（python run.py --version 或 --help 横幅）
```

## 1. 验收步骤（逐项打勾）

### A. 分享链接下载（v2.0.3 主路径，必做）

1. **启动链接模式**
   - CLI：`python run.py --channels-link "https://weixin.qq.com/sph/<id>"`
     （在微信里对目标视频「分享 → 复制链接」取得；也可直接粘贴整段分享文案）
   - 或网页控制台「视频号」页 → 「分享链接下载」输入框 → 识别并下载
   - [ ] 提示「已识别视频号分享链接（id: xxx）」
   - [ ] 系统代理被接管（设置 → 代理指向 127.0.0.1:<端口>）

2. **在微信中打开链接**
   - [ ] 工具尝试自动唤起（失败时按提示手动打开：把链接发到「文件传输助手」
     再点击，或浏览器打开后选「在微信中打开」）
   - [ ] 微信内置浏览器打开视频号**预览页**（显示目标视频）

3. **自动捕获并下载**
   - [ ] Web 控制台「嗅探链路诊断」的 **Feed 获取** 变 ✓（strategy 显示
     `page_network_hook` 或 `passive_response`）
   - [ ] 捕获列表出现该视频并自动开始下载
   - [ ] `Downloaded/` 下出现文件；CLI 模式下载成功后自动结束会话并还原代理

4. **文件可播放**
   - [ ] 本地播放器打开：有画面有声音
   - [ ] 若提示「预览页直链未下发解密密钥」：该视频直链为加密流，记录到
     「已知边界」，不算阻塞（页面按钮路径另行验收）

### B. 页面按钮与刷视频捕获（v2.0.2 路径，尽力验收）

5. **启动视频号模式**
   - CLI：`python run.py --channels`
   - 或网页控制台「视频号」页 → 启动嗅探
   - [ ] 首次运行弹出 Windows 证书确认框，点「是」后提示「根证书已加入信任存储」
   - [ ] 提示「嗅探代理已启动 127.0.0.1:<端口> 并接管系统代理」

6. **微信正常联网**
   - [ ] 打开微信（若会话前微信已运行，**先彻底退出再启动**——运行中的
     微信不会读到新的代理设置）
   - [ ] 微信聊天 / 搜一搜等非视频号功能正常（证明代理没有破坏普通流量）

7. **打开视频号首页**
   - [ ] 微信左侧进入「视频号」，首页正常加载
   - [ ] 视频自动播放

8. **页面出现下载按钮**
   - [ ] 当前视频的操作按钮区域（点赞/评论那一行）出现绿色的「下载」小
     按钮；找不到该区域时页面右下角出现悬浮「下载」按钮（两种都算通过，
     报告里注明实际出现在哪种位置）

9. **切换视频按钮仍存在**
   - [ ] 上滑/下滑切换 3 次视频，「下载」按钮始终在位（ MutationObserver
     重挂生效）

10. **点击下载（第 1 个视频）**
    - [ ] 点击「下载」→ 出现菜单（下载 / 下载最高画质 / 下载最低画质 /
      下载封面，按当前 feed 能力显示）
    - [ ] 若提示「尚未识别当前视频」：见第 14 项诊断路径（微信内页面数据
      经原生桥接，当前版本 A/B/C 策略对 `/web/pages/*` 无效——**已知限制**，
      用分享链接路径覆盖同一目标即算通过）

### C. 直播与收尾

11. **直播回放**
    - [ ] 找一个直播回放视频，用分享链接路径（A 组）下载成功且可播放

12. **正在进行的直播（如当时有）**
    - [ ] 进入直播间，出现「开始录制」按钮
    - [ ] 点击后变「停止录制」；点「停止录制」后 `Downloaded/` 下出现
      部分 `.flv` 文件且可播放
    - [ ] （无进行中直播时填 N/A，用回放覆盖）

13. **停止后系统代理恢复**
    - [ ] Ctrl+C（CLI）或点「停止」（Web）后提示「系统代理已还原」
    - [ ] 系统设置 → 网络 → 代理，确认恢复到启动前的状态
    - [ ] 微信刷新页面恢复正常

## 2. 失败分级自查（对照 Web 控制台「嗅探链路诊断」卡片）

诊断卡片展示九级状态链，第一个 ✗ 即断点：

| 断点 | 计数器特征 | 含义与处置 |
| --- | --- | --- |
| 代理连接 ✗ | `proxy_connections = 0` | 微信没有走系统代理：确认微信是在启动嗅探**之后**打开的；检查 VPN/加速器 |
| 目标域命中 ✗ | `proxy_connections > 0` 且 `target_domain_connections = 0` | 有代理流量但没有视频号域：确认进了视频号页面；检查 `channels.intercept_domains` |
| HTML 拦截 ✗ | `html_pages_seen = 0` | 命中了域但没看到页面 HTML：等页面完整加载；反馈微信版本号 |
| 脚本注入 ✗ | `html_pages_seen > 0` 且 `injected_pages = 0` | 页面看到了但注入失败：看服务端日志注入错误，反馈微信版本号 |
| 前端心跳 ✗ | `injected_pages > 0` 且 `frontend_heartbeat = 0` | 脚本写入了但没执行：CSP / 页面结构问题，反馈微信版本号 |
| 页面按钮 ✗ | `frontend_heartbeat > 0` 且 `buttons_created = 0` | 脚本在跑但按钮没挂上：播放视频 1–2 秒或切换一次；反馈微信版本号 |
| Feed 获取 ✗ | `buttons_created > 0` 且 `parsed_feeds = 0` | 按钮在跑但数据捕获规则失效：**微信内页面数据经原生桥接下发（不走 HTTP）是已实证结论**——改用分享链接路径（A 组）；同时把诊断里的 `runtime_probe`（hooked/fetch_hooked/xhr_hooked/index_size/window_keys/video）与 `candidate_paths` 一并反馈 |
| 下载成功 ✗ | `parsed_feeds > 0` 但下载失败 | 才进入 CDN / decodeKey / ISAAC64 排查：看捕获列表里的失败原因 |

同时记录「捕获策略」分布（诊断卡片标题行）：`page_network_hook` /
`page_runtime_hook` / `passive_response` 各自的条数——用于判断当前是
哪条策略在供数。

## 4. 已知边界（验收前知晓）

- 微信未登录时视频号页面本身不可用，验收需登录态；
- 「未登录时仅能翻页首页」的限制来自微信服务端，与本工具无关；
- 直播录制依赖本机 ffmpeg；未安装时按钮会提示失败原因；
- 自动下载默认关闭（`channels.auto_download: false`）：刷视频只捕获，
  点按钮才下载。想恢复旧行为在配置里改 `true`。
