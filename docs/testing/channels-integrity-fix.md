# 视频号短片与不可播放问题排查记录

日期：2026-09-26。用户现象：下载结果只有几秒，大部分不能播放。

## 证据与定位

原有测试基线为 321 项视频号 Python 测试和 49 项前端测试，全部通过。
但 MSE 测试用 `ftyp` 加填充字节模拟视频，没有验证真实媒体的完整性。

工作目录中找到 4 个既有 `channels_mse-*.mp4` 样本：3 个为约 10.12 秒，
1 个为约 10.54 秒。它们都是 HEVC/AAC，FFmpeg 全量解码退出码为 0。
因此这 4 个样本不能证明“字节已损坏”；播放器缺乏 HEVC 支持是需要处理的
兼容性因素。没有原视频完整时长和当前微信会话，不能确认这些样本各缺少多少内容。

独立构造并运行以下失败测试，复现了与反馈一致的故障类型：

| 路径 | 修复前的失败信号 | 原因 |
| --- | --- | --- |
| MSE 自动保存 | 60 秒媒体只有 0–2 秒缓存，触发 sourceended 后仍发送 begin/chunk/end | 把结束事件、切换与淘汰当作“完整”，不检查缓冲覆盖 |
| MSE 后端 | 有 ftyp 的垃圾字节也登记为 done | 只检查文件头，未验证音视频轨或解码 |
| MSE 后端 | 声称目标 60 秒，实际有效媒体 2 秒，仍登记为 done | 不核对实际时长 |
| 实验性回放拼接 | 与目标无关的有效 MP4 头也被接受 | `cipher XOR (plain XOR cipher)` 恒等于 `plain`，不能证明解密正确 |

复现命令：

```powershell
.venv\Scripts\python.exe -m pytest tests/test_channels_media_integrity.py -q
node --test --test-name-pattern="两秒缓存" tests/frontend/bootstrap_smoke.test.js
```

最初 3 项后端回归测试均失败，前端短片回归测试也失败；修复后均通过。

## 修复内容

1. 前端记录每条 SourceBuffer 的连续缓冲区间、已知最大时长，并等待加载结束。
   `appendBuffer` 导致的临时时长增长不触发保存；跳播缺口、提前切换、容量截断
   均不能冒充完整下载。各音视频轨全部满足完整性条件才能提交。
2. 分离音视频轨一起上传，后端合并成一份文件，不再丢弃纯音频轨。
3. 后端对每轨完整解码并核对目标时长，通过后才生成 faststart MP4、登记历史。
   非 H.264 视频转为 H.264，音频输出 AAC；已有 H.264 视频保留编码，避免无谓损失。
4. 校验与合并在工作线程执行，代理事件循环保持响应。停止会话时等待在途处理和
   历史登记完成，并清理未完成上传，避免关闭数据库后再登记。
5. 大 append 分片严格拆成不超过 2 MiB 的二进制批次，避免 base64 后超过
   虚拟接口 4 MiB 上限。逐批编码，避免一次生成全片 base64。
6. 成功后才写去重标记；失败可以重试。指纹包含媒体内容与长度，避免共享
   初始化头的不同视频被误判为同一个视频。
7. CLI 与 Server 停用无法验证的回放头部拼接及对应后台密文拉取；旧入口也拒绝
   这种伪解密。取得 decodeKey 的普通下载路径保留。
8. 界面与命令行提示同步说明完整播放要求；MSE 临时文件存放在项目 logs 下。

## 使用与尚未验证的边界

重启本项目下载服务，并关闭后重新打开微信内的视频号页面，使新注入脚本生效。
无 decodeKey 时，请从头连续播放并等待完整加载，避免提前切换或拖动跳播。
转码阶段可能需要等待；校验不通过会返回错误，不再生成“成功”的短片。

当前 MSE 单轨内存上限仍为 384 MiB，超过上限不能保存为完整视频。没有解密
密钥时，长回放不能通过播放几秒就恢复全片。已有短文件不含的内容无法凭空补齐。
如果微信播放发生在原生播放器或 Worker 中，当前页面的 MSE hook 也可能无法捕获。

本次完成源码修复、离线链路回归和真实本地媒体验证；未进行微信在线端到端验收，
也未安装证书、切换系统代理或修改用户环境。在线验收仍应选择一条已知完整时长的
目标视频，对比输出时长、声音、末尾画面，并验证提前切换不会登记成功。

技术依据：[W3C MSE 规范](https://www.w3.org/TR/media-source-2/) 中 duration、
buffered 与 sourceended 的定义，以及 [FFmpeg 官方文档](https://ffmpeg.org/ffmpeg.html)
中的解码错误处理、流映射与 MP4 输出选项。
